> **実務でありがちな「詰め切れていない要件定義書」を再現するため、意図的に曖昧な部分を残しています。**

> （講師向け：曖昧な箇所には演習後に解説できるよう、あえて注釈を付けていません。受講者自身に気づかせてください）

## 1. 背景・目的

複数人のチームでタスクの進捗を共有できる、シンプルなタスク管理システムが欲しい。
既存のツール（Trello、Backlog等）は多機能すぎるので、自分たちのチームに必要な機能だけを
持った小規模なアプリケーションを内製したい。

## 2. 想定ユーザー

- 5〜10名程度の小規模開発チーム
- 全員がGitHubアカウントを持っている

## 3. 機能要件

### 3.1 ログイン

- GitHubアカウントでログインできること

> **【研修上の扱い】この機能はすでに実装済みです。**
> 認証は演習の対象外とし、`.env` に GitHub OAuth App の情報を設定すれば動作します。
> 設計・実装の演習では、3.2 以降の機能に集中してください。
> なお、ログインしたユーザーは `User` テーブルに登録されるため、
> 担当者アサインの設計を行う際は、この `User` モデルとの関連を考えることになります。

### 3.2 プロジェクト

- ユーザーはプロジェクトを作成できる
- プロジェクトには名前と説明を付けられる
- プロジェクトの一覧が見られる

### 3.3 タスク

- プロジェクトの中にタスクを作成できる
- タスクには以下の情報を持たせる
  - タイトル
  - 詳細説明
  - ステータス（未着手・進行中・完了）
  - タグ
  - 担当者
- タスクの一覧はステータスごとに見やすく表示する

### 3.4 コメント

- タスクに対してコメントを残せるようにしたい
- チームメンバーであれば誰でもコメントできる

### 3.5 その他

- スマホからも見られるようにしてほしい
- 将来的には他のチームにも展開したいので、拡張しやすい作りにしておいてほしい

## 4. 非機能要件

- 特に厳しいパフォーマンス要件はないが、サクサク動く印象にしたい
- セキュリティは一般的な水準で問題ない

## 5. 参考

- 社内の別チームが使っているスプレッドシート管理から移行する想定
- デザインは凝ったものでなくてよいが、最低限見やすくしてほしい
