# 各モジュール共通プロンプト例集

演習中にそのまま参考にできるプロンプト例です。お題アプリの文脈に合わせて、
固有名詞（テーブル名・機能名など）を実際のものに置き換えて使ってください。

## 設計フェーズ（Module 4）

- 「このアプリの要件から、必要なデータベーステーブルとカラムを提案してください。理由も添えてください」
- 「担当者アサイン機能を追加する場合、多対多と1対多のどちらの設計が適切か、トレードオフを整理してください」
- 「`docs/requirements.md` を読んで、設計を進める上で確認すべき曖昧な点をリストアップしてください」

## 実装フェーズ（Module 5）

- 「タスクのステータス更新APIを実装してください。実装前に方針を説明してから進めてください」
- 「今の変更内容を確認してから、コミットメッセージの案を3つ提示してください」

## テスト・レビュー（Module 6）

- 「このAPIエンドポイントに対するテストケースを、正常系・異常系それぞれ洗い出してから実装してください」
- 「このバグ報告を元に、原因の仮説を3つ立ててから調査を進めてください」（`exercises/debug-task-status/README.md` 参照）

## MCP連携（Module 7）

- 「接続したデータベースの現在のテーブル構成を確認してください」
- 「このテーブルのデータを見ながら、コメント機能のAPIを実装してください」

## CI/CD・リリース（Module 9・10）

- 「このPull Requestに対するレビューコメントを踏まえて、修正方針を提示してから修正してください」
- 「デプロイ後、主要なエンドポイントが正常に応答するか確認する手順を提示してください」
